Repository tools are grouped by the responsibility they own, so adding another formatter or
hook runner does not turn this page into a flat catalog.

| Domain                                                              | Responsibility                                       | Included guidance                |
| ------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------- |
| [Toolchains](/docs/development/repository-tooling/toolchains)       | Runtime, dependency, and package-release tooling     | Mise, npm, pnpm, pip, uv, Poetry |
| [Formatting](/docs/development/repository-tooling/formatting)       | Deterministic source and document formatting         | Prettier                         |
| [Linting and quality](/docs/development/repository-tooling/linting) | Static analysis, style rules, and specialized checks | ESLint, Markdownlint, Lychee     |
| [Git hooks](/docs/development/repository-tooling/hooks)             | Fast local checks around commits and pushes          | Husky, pre-commit                |
| [Automation](/docs/development/repository-tooling/automation)       | Reusable scripts, CI gates, and delivery workflows   | CI/CD, scripting layers          |

Hooks provide fast local feedback; CI remains authoritative because hooks can be skipped.

- [CI/CD and quality gates](/docs/development/repository-tooling/automation/ci-cd) explains when to add Markdownlint, Lychee, ShellCheck,
  actionlint, security checks, tests, builds, and deployment stages.
- [Repository scripting layers](/docs/development/repository-tooling/automation/scripting-layer) shows how to keep reusable automation out of
  workflow YAML and flat script dumps.
