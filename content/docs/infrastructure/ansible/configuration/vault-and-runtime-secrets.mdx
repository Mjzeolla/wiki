Ansible Vault encrypts supported data at rest so it can be stored without plaintext contents.
Authorized execution decrypts it for use. This is different from a long-running secret service,
which issues credentials or authorizes reads at runtime. Do not confuse **Ansible Vault** with
HashiCorp Vault or OpenBao simply because the names overlap.

A common input naming convention is `vault_application_token`; a play maps it to the role variable
that consumes it. The prefix is descriptive only. Use actual Vault encryption and protect the
password/key material independently. See the
[Vault guide](https://docs.ansible.com/projects/ansible/latest/vault_guide/index.html).

## Decryption is only one boundary

The plaintext can later appear in task arguments, a rendered file, module results, diffs, logs,
process environments, or a copied support artifact. Treat every representation according to its
purpose and retention. A secret-bearing task may need `no_log: true`, restricted file modes,
and diff suppression. That does not make unrelated debug tasks safe to dump the same variable.

Prefer password prompts or an approved protected password-file/identity mechanism over putting
passwords in shell arguments. Do not paste a decrypted inventory into a pull request to demonstrate
that variable precedence is correct. Assert types/presence/relationships with appropriately redacted output.

## Rotation includes the consumer

Updating the encrypted source does not restart a service or update every application's live
connection. The play must render or deliver the new value, trigger the appropriate service action,
and verify reconnects. Coordinate overlap and revocation with the upstream provider so rotation
does not remove the only usable credential before consumers have changed.

For Kubernetes applications, External Secrets may own runtime delivery instead of Ansible. Avoid
making both systems write the same Kubernetes Secret. Decide who owns generation, delivery,
rotation, and recovery; let the other layer reference that contract.

## Recovery must survive loss of the controller

Back up the encrypted content and independent recovery material. Test that an authorized operator
can decrypt and safely execute the required recovery procedure from another workstation. Storing
the sole decryption password in the cluster being restored creates an availability cycle.
