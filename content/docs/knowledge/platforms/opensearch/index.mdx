[OpenSearch](https://docs.opensearch.org/latest/about/) is a distributed search and analytics engine
built around JSON documents, inverted indexes, and a REST API. A cluster divides indexes into primary
shards, distributes those shards across data nodes, and optionally maintains replica copies for
availability and read capacity.

Use OpenSearch when the problem needs full-text relevance, faceting and aggregations, log or event
exploration, or retrieval across denormalized documents. It is not a relational source of truth:
cross-document transactions, joins, and strongly normalized update workflows are usually better
owned by a transactional database and projected into OpenSearch.

## Mental model

```text
application -> index/alias -> primary shards -> Lucene segments
                           \-> replica shards on other nodes
```

- A **document** is a JSON object addressed by an index and document ID.
- A **mapping** defines how fields are indexed and queried.
- An **analyzer** converts text into searchable tokens at index and query time.
- An **index** is a logical collection backed by one or more primary shards.
- A **replica** is another copy of a primary shard and is never allocated on the same node as its
  primary.
- An **alias** provides a stable application-facing name across index versions or lifecycle changes.

Start with the question being answered, then design mappings and queries together. Shard count,
field types, analyzers, and document shape are expensive to change after substantial data exists.
Use versioned indexes and aliases when a mapping change requires reindexing.
