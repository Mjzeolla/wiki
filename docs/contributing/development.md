# Development standards

## Toolchain

Mise pins Node and pnpm. The repository uses:

- Next.js and Fumadocs for rendering and content collections;
- `@knotaru/docs-ui` for shared Fumadocs primitives;
- TypeScript in strict mode;
- ESLint for source correctness;
- Prettier for formatting;
- Markdownlint for Markdown and MDX structure;
- the Knotaru content-link checker for local pages and anchors; and
- Lychee for external and file-link validation; and
- Husky for versioned `pre-commit` and `pre-push` hooks.

Husky is the hook manager; this repository does not also install the Python `pre-commit`
framework.

The `pre-commit` hook runs Prettier in write mode before the read-only Markdown, ESLint, and local-link
checks. Review `git status` after a commit: formatting can update files outside the staged snapshot,
and Git does not automatically add newly changed files. CI and `make check` continue to use
`prettier --check` so validation never rewrites the checkout.

## Commands

```bash
make setup         # install pinned tools, dependencies, and hooks
make dev           # start the development server
make check         # lint, Markdown, format, type, and content-link checks
make ci            # checks plus a production build
make validate      # explicit alias for the complete deterministic validation suite
make links         # local content targets plus external URLs
make format        # apply formatting
make markdown-fix  # apply safe Markdownlint fixes
make hooks         # reinstall Git hooks
```

The production build validates rendering of the generated route map. Local content validation
catches missing pages and anchors referenced by Markdown. The route-manifest validator derives
routes from MDX files and rejects invalid redirect destinations, duplicates, chains, and redirects
that shadow live pages. Lychee checks HTTP and HTTPS URLs only; Fumadocs route links are intentionally
left to the content-aware validator rather than interpreted as literal filesystem paths. External
checks run outside `make validate` because remote sites can be unavailable or rate limited
independently of this repository.

## Dependency direction

- Routes may depend on `src/lib/` and `src/config/`.
- Libraries may depend on configuration but not on route modules.
- Content may use the registered MDX component set but should not import application
  internals directly.
- Local code should not duplicate behavior already owned by `@knotaru/docs-ui`.

## Generated output

Fumadocs generates `.source/`, and Next.js generates `.next/` and `next-env.d.ts`. Generated
directories are ignored. `next-env.d.ts` may be regenerated by Next.js and should not be
edited manually.
